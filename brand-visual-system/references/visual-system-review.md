# Visual-system review

Use this when a user has existing work and wants an audit or an update. Review
the requested surfaces before proposing changes.

## Record separately

- **Confirmed:** visible rules that recur consistently or an authoritative source
  explicitly states.
- **Inferred:** plausible patterns that need confirmation.
- **Contradictory:** rules, assets, or examples that conflict.
- **Missing:** a decision required to make the next piece of work consistent.

## Review by system layer

1. **Purpose and audience:** Does the visual work support the intended message
   and setting?
2. **Hierarchy:** Can people find the main action, heading, evidence, and
   supporting material in a sensible order?
3. **Typography:** Are roles, sizes, weights, line lengths, and fallbacks
   consistent and readable?
4. **Color:** Does each color have a job, adequate contrast, and a stable state
   meaning?
5. **Layout:** Do grid, spacing, density, and responsive behavior repeat?
6. **Components:** Do controls, cards, labels, tables, forms, and states follow
   the same rules?
7. **Imagery:** Do subjects, crops, treatments, and text overlays follow a
   coherent direction?
8. **Accessibility and implementation:** Which claims need a browser, design
   file, or assistive-technology check before release?

Return the smallest useful set of changes. Name the evidence for each material
recommendation.
